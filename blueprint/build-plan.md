## Your features

- [x] 1. **Core agent identity & persona** - one shared identity (`core/persona.py`)
      across voice and text channels, third-person representation of Gichogu,
      spoken-vs-written formatting rules
- [x] 2. **Text chat agent** - Agno `site-agent` served through AgentOS, markdown
      responses with knowledge citations (`backend/server.py`)
- [x] 3. **Real-time voice agent** - LiveKit WebRTC worker + Deepgram Nova-3 STT /
      Flux TTS bridge (`backend/livekit_worker.py`, `/ws/voice`, `/ws/deepgram-agent`)
- [x] 4. **RAG knowledge base** - curated content (bio, experience, FAQ, projects,
      skills) chunked and embedded via DeepInfra into Postgres/pgvector, retrieved
      by both agents (`core/knowledge.py`, `core/tools/about.py`)
- [x] 5. **Session & memory persistence** - Postgres-backed Agno `db` shared by
      both agents, degrades gracefully when unavailable
- [x] 6. **Cal.com booking handoff** - hands visitors the public booking link
      rather than scheduling via API (`core/tools/booking.py`)
- [x] 7. **Lead capture & notification** - persists leads to Postgres, best-effort
      email notification to the owner (`core/tools/leads.py`)
- [x] 8. **Gmail drafting via Composio** - scoped allowlist (`notify` / `read` /
      `full`) so a public-facing agent can't send or delete mail by default
      (`core/tools/gmail.py`)
- [x] 9. **Web search fallback** - DuckDuckGo/ddgs search tool for questions
      outside the knowledge base (`core/tools/search.py`)
- [x] 10. **MCP server** - FastMCP server exposing the same core tools to external
       MCP clients (`backend/voice_mcp/voice_agent_server.py`)
- [x] 11. **Frontend chat UI** - Next.js 15 chat interface with sessions, streaming
       responses, markdown rendering, multimedia messages (`frontend/src/components/chat/`)
- [x] 12. **Frontend voice UI** - LiveKit voice modal, control bar, and visualizer
       (`frontend/src/components/voice/`)
- [x] 13. **Feature-flag status endpoint** - `/api/info` reports which optional
       features (persistence, knowledge, booking, leads, gmail) are actually
       configured and live

- [ ] 14. **Interactive tool rendering** - booking card and lead-capture form
       rendered from tool results in text chat, replacing prose-only tool output
       (`frontend/src/components/chat/ChatArea/Messages/`, `core/tools/`)
