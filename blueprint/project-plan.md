## 1. Problem - What problem are we solving?

Gichogu Macharia's personal website needs an always-available way to represent
him to visitors: answer questions about his background, projects, and skills
accurately (not generically), and convert interested visitors into booked
consultations or captured leads — by voice or by text chat.

## 2. Users - Who is this for?

Visitors to gichogumacharia.tech: recruiters, prospective clients, and other
site visitors who want to learn about Gichogu's work and, in some cases, book
time with him or leave contact details.

## 3. Features - What does the MVP need?

Already shipped (see `build-plan.md` for the checked-off list):

- Real-time voice conversation via LiveKit WebRTC + Deepgram STT/TTS
- Text chat with the same agent identity, rendered with markdown and citations
- RAG knowledge base over curated bio/experience/FAQ/projects/skills content
- Cal.com booking handoff (link, not live API scheduling — deliberate, see
  `backend/core/tools/booking.py`)
- Lead capture to Postgres with best-effort owner email notification
- Gmail drafting via Composio, scoped by an explicit allowlist (`GMAIL_SCOPE`)
- Web search fallback for questions outside the knowledge base
- Session/memory persistence in Postgres (shared by voice and text agents)
- MCP server exposing the voice agent's tools (`backend/voice_mcp/`)
- `/api/info` feature-flag endpoint so the frontend knows what's actually live

Current focus (per interview): no new feature scope — the priority is
hardening and debugging the shipped product to end-product quality rather than
adding features.

## 4. Data - What are we storing?

- Sessions, agent memory, and run metrics (Agno's Postgres-backed `db`)
- Knowledge base content and vector embeddings (pgvector)
- Captured leads (contact details from `core/tools/leads.py`)

## 5. Tech - What stack are we using?

- **Backend**: Python 3.13, FastAPI, Agno AgentOS, `uv` for dependency
  management
- **Voice pipeline**: LiveKit Agents (WebRTC), Deepgram (Nova-3 STT, Flux TTS)
- **LLM**: Bedrock (DeepSeek v3.2) first if configured, then xAI Grok, then
  OpenAI `gpt-4o-mini` as fallback — see `backend/server.py` model selection
- **RAG**: Postgres + pgvector, DeepInfra embeddings (`bge-base-en-v1.5`, 768
  dims)
- **Integrations**: Cal.com (booking link), Composio (Gmail), DuckDuckGo/ddgs
  (web search)
- **Frontend**: Next.js 15, React 18, Tailwind, Radix UI, `@livekit/components-react`,
  pnpm
- **MCP**: FastMCP server wrapping the same core tools for external MCP clients

Confirmed intentional as-is by the interview — no legacy parts to flag.

## 7. UI/UX - How should this look and feel?

Per `backend/core/persona.py`: warm, relaxed, quietly confident, genuinely
interested — not performative or hype-driven. Speaks about Gichogu in the
third person and identifies itself as his AI assistant when asked. Voice
responses avoid markdown, use short spoken-friendly sentences and spoken date
formats; text responses use full markdown with citations from retrieved
knowledge.
