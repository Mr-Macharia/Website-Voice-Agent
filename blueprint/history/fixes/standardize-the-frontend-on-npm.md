# Fix: Standardize the frontend on npm

**Type:** Fix
**Status:** verified
**Branch:** fix/standardize-the-frontend-on-npm

## The problem

`frontend/` tracks two lockfiles, `package-lock.json` and `pnpm-lock.yaml`.
Vercel detects the pnpm one and installs with pnpm. The committed
`pnpm-lock.yaml` is stale: it is missing 6 dependencies that `package.json`
declares. So the deploy of `80717e3` fails with `ERR_PNPM_OUTDATED_LOCKFILE`.

The local tooling uses pnpm whenever it is installed:
- `scripts/run.sh` and `scripts/run.py` both run `pnpm dev`.
- The frontend's `validate` script shells out to `pnpm`.

The one real use of the pnpm-specific config is `package.json`'s
`"pnpm": {"overrides": {"picomatch": ">=2.3.2"}}`, a security pin. npm ignores
that key, although `package-lock.json` already resolves `picomatch` to 2.3.2 and
4.0.5.

The user chose npm as the single package manager (option A).

## The fix

1. **Lockfile.** Remove `frontend/pnpm-lock.yaml` from git and discard the
   local pnpm-12 changes to it. Delete the untracked
   `frontend/pnpm-workspace.yaml`.
2. **Security pin.** Move the `picomatch` pin from `"pnpm".overrides` to npm's
   top-level `"overrides"` so it still holds. Refresh the lockfile with
   `npm install --package-lock-only`. Accept the `package-lock.json` diff only
   if it is limited to override bookkeeping. If other versions move, stop and
   report.
3. **Scripts.**
   - `scripts/run.sh` and `scripts/run.py` start the frontend with `npm run dev`
     and no longer prefer pnpm.
   - `frontend/package.json`'s `validate` uses `npm run`.
4. **Docs.** Change "pnpm-managed" to npm in the places that describe current
   tooling:
   - `AGENTS.md:253`
   - `README.md:105`
   - `frontend/README.md:51,57`
   - `blueprint/context/coding-standards.md:14`

   Leave `blueprint/project-plan.md` and `project-overview.md` alone. They
   belong to the user and are regenerated by `/overview`; I'll flag them
   instead.

**Must not break:** `npm run dev:all`, `npm run dev:sh:all`, the frontend
build, and the Vercel install. The Vercel install should work with the
dashboard override either on (`npm install`) or off, because Vercel
auto-detects npm once only `package-lock.json` remains.

**Out of scope:**
- F-15 (removing `livekit-server-sdk`).
- Upgrading any dependency.

## Build steps

- [x] **1. Switch to npm.** Make changes 1–4 above.
  **Done when:**
  - `git ls-files frontend | grep -i pnpm` returns nothing.
  - `grep -n pnpm scripts/run.sh scripts/run.py frontend/package.json` returns
    nothing.
  - `cd frontend && npm ci` succeeds against the committed lockfile.
  - `npm ls picomatch` shows no version below 2.3.2.
  - `cd frontend && npm run validate` passes. Its lint, format and typecheck
    all run through npm now; the format step checks the whole frontend, so
    already-unformatted files would make it fail — report any that do.
  - `cd frontend && npm run build` passes.

## Verify

- Locally, `npm run dev:sh:all` starts the frontend via `npm run dev`, and the
  site loads on :3000.
- After merge and push, the Vercel log shows npm doing the install (no
  "Detected pnpm-lock.yaml"), and the build succeeds.
